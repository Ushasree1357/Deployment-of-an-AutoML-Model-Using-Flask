# Deployment of an AutoML Model Using Flask

A small Iris classification web app for a BTech CSE AIML demonstration. The training script compares several scikit-learn model families and hyperparameters with five-fold cross-validation, saves the best pipeline and its evaluation results, and Flask serves predictions from that saved artifact.

## Project contents

```text
automl-flask-project/
|-- app.py
|-- train_model.py
|-- model.pkl                 # Generated by train_model.py; included after training
|-- requirements.txt
|-- README.md
|-- templates/
|   `-- index.html
`-- static/
    `-- style.css
```

The dataset is loaded locally from `sklearn.datasets.load_iris`; no data download is required. The four input features are sepal length, sepal width, petal length, and petal width in centimeters. The target labels are Setosa, Versicolor, and Virginica.

## Setup and run on Windows

Open PowerShell in this project folder:

```powershell
cd "path\to\automl-flask-project"
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python train_model.py
python app.py
```

If PowerShell blocks activation, allow activation for the current terminal with `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, then activate the environment again. Use Python 3.10-3.13 if Python 3.12 is not available; Auto-sklearn is intentionally not a dependency because it is not reliably supported on Windows.

Open <http://127.0.0.1:5000> in a browser. Use the Reset link to clear the form. Train the model again after changing the training script or dependencies.

## Training and evaluation workflow

1. Load Iris as a pandas feature table and target labels.
2. Make a stratified 80/20 train/test split with a fixed seed.
3. Run a five-fold `GridSearchCV` over Logistic Regression, SVC, Random Forest, Extra Trees, and Decision Tree configurations. Standardization is kept inside a scikit-learn pipeline, so it is fit independently inside each cross-validation fold and then on all training data for the final model.
4. Select the configuration with the best mean cross-validation accuracy.
5. Evaluate the selected model once on the held-out test data and calculate accuracy, precision, recall, and F1-score.
6. Save the fitted pipeline, selected estimator name, feature and target names, accuracy, and per-class report to `model.pkl` with Joblib.
7. Flask loads that bundle, validates four posted measurements, calls `predict` and `predict_proba`, and renders the predicted class and confidence.

The included artifact was trained with a stratified split and produced 97.50% best cross-validation accuracy and 93.33% held-out accuracy in the current environment. Results can vary slightly across scikit-learn versions.

## Architecture

```text
Browser form
    | POST /predict (four measurements)
    v
Flask app.py -> input validation -> saved preprocessing/model pipeline
    |                                      |
    | rendered prediction + confidence    | class probabilities
    v                                      v
HTML/Jinja template <------------------- Joblib model.pkl
         ^                                  ^
         |                                  |
         +-- evaluation metrics      train_model.py
                                           ^
                                           |
                           Iris dataset -> model search -> test metrics
```

`GridSearchCV` is the compatible AutoML alternative in this project: it automates candidate estimator and parameter comparison. It is an educational, bounded search rather than a claim to cover every model or tuning strategy. Accuracy is the percentage of test observations classified correctly; precision measures the correctness of predicted class labels, recall measures how many actual class members were found, and F1 is their harmonic mean. The confidence shown is the chosen model's highest predicted class probability, not a guarantee of correctness.

## Viva questions and answers

1. **What is AutoML?** AutoML automates parts of the machine-learning workflow, such as comparing algorithms, choosing hyperparameters, and selecting a candidate model.
2. **Why use GridSearchCV here?** It provides a reproducible scikit-learn-native search that runs on Windows and compares a defined set of estimators and parameters with cross-validation.
3. **Why split training and test data?** The test partition is kept out of model selection and gives a final estimate of generalization to unseen examples.
4. **What does stratified splitting do?** It preserves approximately the same proportion of each Iris species in both partitions.
5. **Why is scaling in a pipeline?** It ensures the scaler is fitted only on each training fold during CV, preventing data leakage, and applies the same transformation during deployment.
6. **What is cross-validation?** The training data is divided into folds; each fold is validated once while the others are used for fitting, and the scores are averaged.
7. **What does accuracy mean?** The fraction of predictions that match their true labels. It should be considered alongside per-class precision, recall, and F1.
8. **What is a confusion matrix?** A table that counts actual-versus-predicted labels and shows which classes are confused. It can be added as another evaluation view.
9. **Why serialize a model?** Joblib persists the fitted estimator and preprocessing pipeline so Flask can make predictions without retraining for every request.
10. **What role does Flask play?** Flask receives HTTP requests, validates input, invokes the saved model, and returns a rendered HTML response.
11. **What is the difference between training and inference?** Training searches and fits candidate models using labeled data; inference applies the chosen, already-fitted model to a new flower's measurements.
12. **What does prediction confidence represent?** The model's estimated probability for its most likely class; it is not necessarily calibrated or a guarantee of accuracy.
13. **Why validate inputs on the server?** Browser-side validation can be bypassed, so the backend must reject missing, nonnumeric, non-finite, or non-positive measurements.
14. **How could the project be improved?** Add automated tests, a confusion matrix, input-range warnings, versioned artifacts, logging, and deployment behind a production WSGI server.

## Notes

- `model.pkl` is a generated binary artifact. Regenerate it with `python train_model.py` when needed.
- Flask runs with debug mode disabled. For public production deployment, use a production WSGI server and appropriate security configuration.
- The UI uses Bootstrap's CSS CDN plus custom responsive styling; Google Fonts are also loaded remotely. The app logic and Iris dataset work without network access after dependencies are installed, though those external visual assets will not load offline.
